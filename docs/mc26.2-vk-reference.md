## 1. 深度格式(spec §7-2)

- 深度附件格式:**VK_FORMAT_D32_SFLOAT**(纯深度,无 stencil)。
  证据:
  - `GpuFormat.java:55`(D32_FLOAT 枚举)→ `VulkanConst.java:161` `D32_FLOAT -> 126`(126 = VK_FORMAT_D32_SFLOAT);
  - 主世界深度纹理:`MainTarget.java:84`(15 层 D32_FLOAT,每 chunk section 一层)、`RenderTarget.java:83`(通用 RT 深度);
  - UI 侧同格式:`PictureInPictureRenderer.java:96`、`GuiItemAtlas.java:46`。
- **Reverse-Z:是**(双曲反转折射,非教科书 [0,1] 归一化形式)。证据链:
  1. 默认深度比较 = **GEQUAL**:`DepthStencilState.java:6` `DEFAULT = new DepthStencilState(CompareOp.GREATER_THAN_OR_EQUAL, true)`;
     `VulkanConst.java:204` `GREATER_THAN_OR_EQUAL -> 6`(VK_COMPARE_OP_GEQUAL);绑定于管线创建 `VulkanRenderPipeline.java:149`。
  2. 深度清除值 = **0.0**(空值/远平面 = 0,所有几何 z > 0):`GameRenderer.java:436`、`GameRenderer.java:568`、`LevelRenderer.java:497`(`clearDepthTexture(..., 0.0)`)。
  3. 投影矩阵 **near/far 互换** + zZeroToOne=true:`Projection.java:67-68`(`near = this.zFar; far = this.zNear;`)
     → `Projection.java:71` `matrix.setPerspective(fov, aspect, near, far, zZeroToOne)`(JOML 1.10.8);
     Vulkan 后端 `isZZeroToOne = true` 硬编码:`VulkanDevice.java:91-95`(`new DeviceInfo(..., true, "Vulkan", ...)`,字段定义 `DeviceInfo.java:9`)。
  4. 数值验证(§7):ndcz(d) = 19.997/d + 0.0031(n=0.05, f=320 时)——近 0.05m→400、10m→2.0、远 320m→0.0656;
     viewport 深度钳制 [0,1](`VulkanRenderPass.java:87-88` minDepth=0, maxDepth=1)→ 距相机 <≈20m 的几何全部钳到 z=1.0,
     远平面落在 0.066,clear=0.0 低于一切几何。
  5. 分布为 1/d 双曲线 → 近处精度 nm 级、远处粗(≈40µm @320m,float32 ULP 估算)——经典 reverse-Z 取舍;
     近处 <20m 共享 z=1.0(GEQUAL 等值通过 → 近景 overdraw、无深度排序,LOD/遮挡测试须注意)。
- 深度比较/清除策略:GEQUAL + clear 0.0(同上);stencil 主流程未使用(纯 D32_SFLOAT)。

## 2. 投影矩阵约定(spec §7-2)

- NDC 原点:**左上**(Vulkan 窗口约定)。+y 世界 → -y NDC:投影矩阵 clip.w < 0 完成翻转(数值验证 ndcY(0,+1) < 0,§7);
  viewport 层不做 Y 翻转(`VulkanRenderPass.java:83-88` y=0, height=正)。
- NDC z 范围:**[0,1]**(isZZeroToOne=true;`VulkanRenderPass.java:87-88`),且**反转**(近=1 最大,远→最小 ≈0.066,见 §1)。
- near/far:near = **0.05F 固定**(`Camera.java:107` `setupPerspective(0.05F, this.depthFar, this.fov, w, h)`);
  far = depthFar = max(renderDistance·16·4, cloudRange·16)(`Camera.java:92`)。
- 投影矩阵构造:`Projection.java:63-75` getMatrix() → JOML `Matrix4f.setPerspective(fovy, aspect, zNear', zFar', zZeroToOne)`;
  每帧写入 `CameraRenderState.projectionMatrix`(`Camera.java:124` extractRenderState),
  提交渲染时 `GameRenderer.java:554` `RenderSystem.setProjectionMatrix(..., ProjectionType.PERSPECTIVE)`。
- 剔除矩阵:`Camera.java:176-184` createProjectionMatrixForCulling()——同一 isZZeroToOne 标志,
  fov 取 max(实际 fov, 设置 fov)(`Camera.java:177`),供 Frustum 剔除用。
- 正交(HUD/PIP/3D HUD):`Projection.java:72-75` `setOrtho(0, w, invertY?h:0, invertY?0:h, near, far, zZeroToOne)`
  ——invertY 参数决定正交路径 Y 向(`Projection.java:24` orthoInvertY)。

## 3. Swapchain 与帧提交结构

- 图像数:minImageCount = **max(3, surfaceCapabilities.minImageCount())**(`VulkanGpuSurface.java:211`),
  requestedImageCount = 3(`VulkanGpuSurface.java:210`);swapchain 创建 `VulkanGpuSurface.java:207-220`。
- 呈现模式:由 GpuSurface.Configuration.presentMode 决定,`Minecraft.java:1230-1233`
  (`GpuSurface.PresentMode.getSupportedVsyncMode(supportedModes, vsync)`,实现 `GpuSurface.java:123`);
  支持集 = IMMEDIATE / MAILBOX / FIFO / FIFO_RELAXED(`VulkanGpuSurface.java:115-124` 枚举物理设备后映射)。
- Acquire:`VulkanGpuSurface.java:280-305` —— acquire semaphore **轮换池**(`currentAcquireSemaphore % acquireSemaphores.length`,
  多帧 in-flight),`vkAcquireNextImageKHR(device, swapchain, 5_000_000_000L(5s), acquireSemaphore, 0L, ...)`;
  result==2(VK_ERROR_DEVICE_LOST/GPU 超时)→ 抛出带 **GPU checkpoint** 的异常(`checkpointExtension().retrieveCheckpoints`,
  Amd/Nvidia checkpoint 扩展 = vulkan/checkpoints/ 子包);-1000001004 = OUT_OF_DATE_KHR(重建 swapchain);1000001003 = SUBOPTIMAL。
- 提交:**Synchronization2 `vkQueueSubmit2KHR(queue, VkSubmitInfo2[], fence=0)`**(`VulkanQueue.java:80-124`):
  每个 SubmitStage(waits: VkSemaphoreSubmitInfo = semaphore+value+stageMask,二进制与 timeline 信号量通吃
  → commandBuffers: VkCommandBufferSubmitInfo → signals: 同 waits 结构);**fenceless(fence=0L),完全信号量驱动**;
  Submission 为 AutoCloseable(close 即触发 submit)。
- 每帧序列:游戏主循环 Minecraft.run → RenderSystem 帧(设备初始化 `Minecraft.java:497` RenderSystem.initRenderer(device))
  → 渲染器在 CommandEncoder 上编码(每个 encoder 持一个 graphics-queue Submission builder:
  `VulkanCommandEncoder.java:85`/`VulkanCommandEncoder.java:200` `device.graphicsQueue().beginSubmit()`)
  → `VulkanGpuSurface.acquireNextImage`(上述)→ 最终渲染目标经 `blitFromTexture`(`VulkanGpuSurface.java:308+`,
  瞬态 command buffer + image barrier)blit 到 swapchain 图像 → Submission.close() 触发 vkQueueSubmit2KHR。

## 6. 着色器工具链现状(2026-09-14 已装 + 冒烟验证)

- 宿主机(Fedora 44)已安装并端到端验证:
  - **glslang 16.2.0**(`dnf install glslang`):/usr/bin/glslangValidator、/usr/bin/glslang;
    注意该包**不含 glslc**(Khronos 的 glslc 包装器未打包),直接以 glslangValidator 替代;
  - **spirv-tools 2026.1**(`dnf install spirv-tools`):/usr/bin/spirv-val、spirv-opt、spirv-dis。
- 标准离线管线(glslc 等价配方,2026-09-14 冒烟测试通过:编译 → spirv-val → 反汇编全绿;
  已封装为 `mod/scripts/compile-spirv.sh`):
  ```bash
  glslangValidator --target-env vulkan1.3 -o out.spv in.vert   # GLSL→SPIR-V(产物为 SPIR-V 1.6 二进制)
  spirv-val --target-env vulkan1.3 out.spv                     # 校验
  spirv-opt --target-env vulkan1.3 -O out.spv                  # 可选:体积/性能优化
  spirv-dis out.spv                                            # 反汇编人工检查
  ```
- 实测踩坑(glslang 16.2 / spirv-tools 2026.1):
  - `--target-env` 取值为 `vulkan1.3` / `spirv1.6` 等(glslang 16 拼法,**不是** `spv1.6`);`vulkan1.3` 隐含 Vulkan 语义(-V);
  - glslangValidator 16.2 **无 `-O` 优化开关**(仅剩 `-Od`/`-Os`),优化一律走 spirv-opt;
  - spirv-tools 2026.1 的 spirv-dis **无 `--disassemble` 参数**(反汇编是默认行为,直接 `spirv-dis file.spv`)。
- 游戏内管线:LWJGL **shaderc 3.4.1 + spvc 3.4.1**(linux/macos/windows natives 全套在 mc-src/artifacts/libs/),
  GLSL→SPIR-V 在 JVM 内完成,入口与后处理在 vulkan/glsl/ 包:
  GlslCompiler.java(编译入口)、SpvcUtil.java(SPIR-V 后处理)、IntermediaryShaderModule.java / SpvVariable.java /
  SpvUniformBuffer.java / SpvSampler.java(SPIR-V 反射与绑定处理)。
  宿主机离线 .spv 与之目标一致:vulkan1.3 目标、SPIR-V 1.6 产物,26.2 设备(Vulkan 1.3 级)可直接 vkCreateShaderModule 加载。
- 阶段二离线 .spv:用上述配方(或 compile-spirv.sh)手工编译,直接丢 mod resources
  (spec §7-5:前期不做 SPIR-V gradle 自动化)。

## 7. 数值验证环境(附录)

- JOML:mc-src/artifacts/libs/joml-1.10.8.jar。setPerspective(fovy, aspect, zNear, zFar, zZeroToOne) 实现
  (Vineflower 1.12.0 反编译,有限 near/far 分支):`m22 = zFar/(zNear-zFar)`、`m32 = zFar·zNear/(zNear-zFar)`、
  `m23 = -1`、`m33 = 0` —— 注意 **clip.w = m32·z**(非经典 GLSL 的 w=-z),zZeroToOne=false 分支为
  `m22 = (zFar+zNear)/(zNear-zFar)`、`m32 = 2·zFar·zNear/(zNear-zFar)`(经典 [-1,1] 变体)。
- 验证程序:会话 /tmp/jomldig/Z2.java(Temurin 25 javac -cp joml-1.10.8.jar),
  采样 d = 0.05 / 0.5 / 2 / 10 / 40 / 100 / 320,fov=1.0 rad,aspect=1。
- MC 实际调用(换序后 n=真实 near=0.05,f=真实 far=320)的精确映射:
  **ndcz(d) = (f - n - n·d)/(n·f·d)** = 19.997/d + 0.0031(n=0.05, f=320);
  实测:d=0.05→399.94(钳 1.0)、d=10→2.0028、d=40→0.5030、d=320→0.0656;ndcY(0,+1) 恒负(Y 翻转)。
